## 概述

Gyro 把"请求应该路由到集群里的哪一台机器"这件事从应用逻辑中剥离出来,通过一致性哈希在客户端内完成路由,不需要额外的代理层。

### 核心特性

- **高性能**:客户端直连,零代理层延迟
- **动态伸缩**:基于增量重平衡的节点管理,扩缩容时只搬迁受影响的分区
- **协议适配**:内置 Redis(go-redis)、gRPC(grpc-go)适配器,拿到的是原生客户端,不做二次封装
- **健康检查**:主动探测,可配置故障/恢复阈值
- **服务发现 + 配置热更新**:节点/配置变化时增量应用,不推倒重建

### 适用场景

1. **分布式缓存**:Redis 等 KV 存储的客户端分片
2. **有状态 gRPC 服务**:游戏服务器、长连接网关等需要"同一个 key 固定路由到同一台机器"的场景
3. **Kubernetes 环境下的动态节点管理**

详见 [Gyro 功能文档](./gyro-feature-documentation-20260814.md) 中的场景分析、项目对比和当前限制。

## 核心概念

### 一致性哈希

Gyro 使用一致性哈希算法(已抽成独立库 [focusandinsist/consistent-go](https://github.com/focusandinsist/consistent-go))决定请求路由到哪个节点,确保:

- **均匀分布**:请求在所有节点间均匀分布
- **最小化重新分配**:添加或删除节点时,只有最少的数据需要重新分配

### 虚拟节点与分区

每个物理节点在哈希环上有多个虚拟节点(默认 20 个),Gyro 使用固定数量的分区(默认 271 个)而不是直接映射键到节点,这样扩缩容时只需要重新分配分区,而不是重新计算所有键。
